## 请求结构

大模型 API 通常包含模型名称、消息列表、采样参数和输出限制。对后端来说，最重要的是把这些参数封装成稳定的服务接口，而不是让业务代码到处拼 Prompt。

## 流式输出

聊天类产品常用流式输出降低等待感。后端可以通过 SSE 或 WebSocket 把模型生成的增量内容推给前端。

```ts
type ChatChunk = {
  id: string;
  delta: string;
  done: boolean;
};
```

## 错误处理

常见错误包括超时、限流、上下文过长、模型暂不可用和内容安全拦截。建议统一封装重试、降级和错误码映射，避免业务层直接依赖供应商错误格式。

## 成本控制

AI 接口是按 Token 计费的。上线前就要记录请求 Token、输出 Token、用户、场景和模型名称，后面才能做账单分析和限额控制。
