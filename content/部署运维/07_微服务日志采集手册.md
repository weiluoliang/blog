## 1. 架构与设计要点

```bash
各服务日志文件 (/home/logs/<服务名>/*.log)
        │
     Filebeat 8.14.3(采集 + 多行合并 + 提取服务名)
        │
   Elasticsearch(Ingest Pipeline 解析字段 + smartcn 中文分词)
        │
      Kibana(按 service / trace_id / 中文关键词查询)
```

- **不需要 Logstash**:解析交给 ES 的 Ingest Pipeline。日志量特别大、需要 Kafka 削峰或多路输出时再考虑。
- **保持现有文本日志格式,不改 JSON**:用 dissect 按 `|` 拆字段。
- **所有服务一个索引**,靠 `service` 字段区分;**按环境分索引**(`jsy-log-dev-*` / `test` / `prod`),各环境保留期不同。
- 用 `trace_id` 串联一次请求在各服务的日志(前提:traceId 跨服务传递)。
- **版本要求**:Filebeat 版本不要高于 ES;ES 是 7.x 的话要用 7.17 的 Filebeat。

## 2. 日志格式约定

Logback 的 pattern:

```bash
%d{yyyy-MM-dd HH:mm:ss.SSS}|%-5level|%t|%c|%X{traceId}|uid=%X{userId}|%m%n
```

示例:

```bash
2026-09-20 10:23:45.123|INFO |http-nio-8080-exec-1|com.olink.device.Service|abc123|uid=1001|设备上线 sn=X1
```

解析后的字段:

| 字段            | 含义                           |
|---------------|------------------------------|
| `@timestamp`  | 日志时间(按 Asia/Shanghai 解析)     |
| `level`       | 日志级别                         |
| `thread`      | 线程名                          |
| `logger`      | 类名                           |
| `trace_id`    | 链路 ID(为空则不存)                 |
| `user_id`     | 用户 ID(为空则不存)                 |
| `msg`         | 日志正文(含多行堆栈)                  |
| `service`     | 服务名,取自日志目录名                  |
| `env`         | 环境:dev / test / prod         |
| `parse_error` | 格式不匹配时为 true,并保留原始 `message` |

> 可选优化:`%c` 输出完整类名很长,可改为 `%logger{40}`,不影响解析。

### 4.2 创建 Ingest Pipeline

```json
PUT _ingest/pipeline/jsy-app-log
{
  "processors": [
    {
      "dissect": {
        "field": "message",
        "pattern": "%{log_time}|%{level}|%{thread}|%{logger}|%{trace_id}|uid=%{user_id}|%{msg}"
      }
    },
    {
      "trim": {
        "field": "level"
      }
    },
    {
      "date": {
        "field": "log_time",
        "formats": [
          "yyyy-MM-dd HH:mm:ss.SSS"
        ],
        "timezone": "Asia/Shanghai",
        "target_field": "@timestamp"
      }
    },
    {
      "remove": {
        "field": "trace_id",
        "if": "ctx.trace_id == ''",
        "ignore_missing": true
      }
    },
    {
      "remove": {
        "field": "user_id",
        "if": "ctx.user_id == ''",
        "ignore_missing": true
      }
    },
    {
      "remove": {
        "field": [
          "log_time",
          "message"
        ]
      }
    }
  ],
  "on_failure": [
    {
      "set": {
        "field": "parse_error",
        "value": true
      }
    }
  ]
}
```

说明:

- `msg` 是最后一个字段,会取剩余全部内容,消息里带 `|`(如设备报文 `A5|01|FF`)不会被切坏。
- `timezone` 必须指定,否则会被当成 UTC,Kibana 里差 8 小时。
- 解析失败的日志不会丢,会带 `parse_error: true` 入库。

用 simulate 验证(三条都对再上线):

```json
POST _ingest/pipeline/jsy-app-log/_simulate

      "_source": {
        "message": "2026-09-20 10:23:45.123|INFO |http-nio-8080-exec-1|com.olink.device.Service|abc123|uid=1001|设备上线 sn=X1"

    {
      "_source": {
        "message": "2026-09-20 10:23:46.001|ERROR|main|com.olink.Foo||uid=|处理失败\njava.lang.NullPointerException\n\tat com.olink.Foo.bar(Foo.java:10)"

}
```

            "filter": [
              "lowercase"

    "mappings": {
      "properties": {
        "env": {
          "type": "keyword"
        },
        "service": {
          "type": "keyword"
        },
        "level": {
          "type": "keyword"
        },
        "thread": {
          "type": "keyword"
        },
        "logger": {
          "type": "keyword"
        },
        "trace_id": {
          "type": "keyword"
        },
        "user_id": {
          "type": "keyword"

## 5. Filebeat 完整配置(`/data/www/filebeat/filebeat-8.14.3-linux-x86_64/filebeat.yml`)

先备份原文件:`cp filebeat.yml filebeat.yml.bak`,再整体覆盖。ES 地址和账号换成实际值。

```yaml
# ==================== 输入 ====================
filebeat.inputs:
  - type: filestream
    id: jsy-all-services
    enabled: true

    paths:
      - /home/logs/*/*.log          # 一级目录:jsy-iot、jsy-wy 等
      - /home/logs/*/*/*.log        # 二级目录:electricity_backend、message-system 等

    # 不采集压缩的历史日志
    prospector.scanner.exclude_files: [ '\.gz$' ]
    # 只采集近 48 小时有更新的文件,避免首次启动扫大量历史文件
    ignore_older: 48h
    clean_inactive: 72h
    # 服务多、文件多,及时释放不再更新的文件句柄
    close.on_state_change.inactive: 5m

    # 环境标识:启动时用变量注入,默认 dev
    fields:
      env: '${ENV:dev}'
    fields_under_root: true

    # 多行合并:以 "2026-09-20 10:23:45.123|" 开头的才算新的一条
    parsers:
      - multiline:
          type: pattern
          pattern: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}\.\d{3}\|'
          negate: true
          match: after
          max_lines: 500
          timeout: 5s

# ==================== 处理 ====================
processors:
  # 丢弃 DEBUG 日志(放在最前面,被丢弃的日志不再走后面的处理)
  - drop_event:
      when:
        regexp:
          message: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}\.\d{3}\|DEBUG\|'
  # 从文件路径提取服务名:/home/logs/jsy-iot/xxx.log -> service=jsy-iot
  - dissect:
      field: "log.file.path"
      tokenizer: "/home/logs/%{service}/%{?rest}"
      target_prefix: ""
      ignore_failure: true
  # 去掉用不上的字段,减少存储
  - drop_fields:
      fields: [ "agent", "ecs", "input", "log.offset" ]
      ignore_missing: true

# ==================== 输出 ====================
output.elasticsearch:
  hosts: [ "http://ES地址:9200" ]
  username: "elastic"
  password: "xxx"
  pipeline: jsy-app-log
  index: "jsy-log-%{[env]}-%{+yyyy.MM.dd}"

# 自定义索引名后这三项必须有;模板和 ILM 由 ES 端手动管理
setup.template.enabled: false
setup.template.name: "jsy-log"
setup.template.pattern: "jsy-log-*"
setup.ilm.enabled: false

# ==================== 日志 ====================
logging.level: info
logging.to_files: true
logging.files:
  path: /data/www/filebeat/filebeat-8.14.3-linux-x86_64/logs
  name: filebeat
  keepfiles: 7
```

要点:

- 一个 input 覆盖所有服务,**新增服务不用改配置**,`service` 自动取目录名。
- 滚动日志不需要额外处理:filestream 按文件指纹识别,0 点重命名压缩后会先读完旧文件再读新文件,不重复不漏。
- `service` 的 tokenizer 里 `/home/logs/` 是写死的,日志目录变了要同步改。
- `filebeat.yml` 含 ES 密码,权限保持 600,属主与运行用户一致。

### 过滤 DEBUG 日志(不上传到 ES)

已在上面的 `processors` 最前面加了 `drop_event`,DEBUG 日志在本机直接丢弃,不会发到 ES。原理:

- 级别在第一个 `|` 之后,`%-5level` 把 DEBUG 补成 5 个字符,所以匹配 `|DEBUG|`。
- 处理器在多行合并**之后**运行,一条 DEBUG 日志连同它的多行内容(长 JSON、换行堆栈)会整体被丢掉,不会残留半截。
- 放在最前面,被丢弃的日志不再走后面的处理,省资源。

**同时丢弃 TRACE**:

```yaml
regexp:
  message: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}\.\d{3}\|(DEBUG|TRACE)\|'
```

**只对部分服务丢弃**:`service` 由 dissect 提取,所以这时 `drop_event` 要放在 dissect 之后:

```yaml
  - drop_event:
      when:
        and:
          - regexp:
              message: '^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}\.\d{3}\|DEBUG\|'
          - or:
              - equals:
                  service: jsy-wy
              - equals:
                  service: jsy-iot
```

**生效**:`./filebeat test config -c filebeat.yml`,然后重启 Filebeat(`systemctl restart filebeat`)。会从上次的读取进度继续,不会重复采集。

**清掉已经入库的 DEBUG**:

```json
POST jsy-log-*/_delete_by_query
{
  "query": {
    "term": {
      "level": "DEBUG"
    }
  }
}
```

**验证**:各级别数量里 `DEBUG` 不再增长即可:

```json
GET jsy-log-dev-*/_search
{
  "size": 0,
  "aggs": {
    "by_level": {
      "terms": {
        "field": "level"
      }
    }
  }
}
```

> Filebeat 过滤只是不上传,DEBUG 仍会写在服务器磁盘上。如果线上不需要 DEBUG,更彻底的做法是把 logback 级别调成
> INFO,从源头不产生;dev 需要排查时再临时开启,Filebeat 的过滤会把它挡在 ES 之外。

### 个别服务格式不同时

如果某个服务(如 `xxl-job-admin`)格式和标准不一致,给它单独一个 input,并在主 input 里排除它:

```yaml
filebeat.inputs:
  - type: filestream
    id: jsy-all-services
    paths:
      - /home/logs/*/*.log
      - /home/logs/*/*/*.log
    prospector.scanner.exclude_files: [ '\.gz$', '/home/logs/xxl-job-admin/' ]
    # ...其余同上

  - type: filestream
    id: xxl-job-admin
    paths:
      - /home/logs/xxl-job-admin/*.log
    prospector.scanner.exclude_files: [ '\.gz$' ]
    ignore_older: 48h
    fields:
      env: '${ENV:dev}'
      service: xxl-job-admin
    fields_under_root: true
    pipeline: xxl-job-log          # 需在 ES 单独建这个 pipeline
    parsers:
      - multiline:
          type: pattern
          pattern: '^\d{4}-\d{2}-\d{2} '   # 按它自己的时间格式改
          negate: true
          match: after
```

## 6. 启动

### 6.1 启动前检查(先确认 ES 里 pipeline 和模板都已创建)

```bash
cd /data/www/filebeat/filebeat-8.14.3-linux-x86_64
./filebeat test config -c filebeat.yml
./filebeat test output -c filebeat.yml
ENV=dev ./filebeat -e -c filebeat.yml      # 前台运行,观察无报错后 Ctrl+C
```

### 6.2 systemd 常驻

`/etc/systemd/system/filebeat.service`:

```ini
[Unit]
Description=Filebeat
Documentation=https://www.elastic.co/beats/filebeat
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
Environment=ENV=dev
WorkingDirectory=/data/www/filebeat/filebeat-8.14.3-linux-x86_64
ExecStart=/data/www/filebeat/filebeat-8.14.3-linux-x86_64/filebeat -e -c /data/www/filebeat/filebeat-8.14.3-linux-x86_64/filebeat.yml --path.home /data/www/filebeat/filebeat-8.14.3-linux-x86_64 --path.config /data/www/filebeat/filebeat-8.14.3-linux-x86_64 --path.data /data/www/filebeat/filebeat-8.14.3-linux-x86_64/data --path.logs /data/www/filebeat/filebeat-8.14.3-linux-x86_64/logs
Restart=always
RestartSec=5
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

**部署到测试、生产机器时,只需要把 `Environment=ENV=` 改成 `test` 或 `prod`**,其余不变。

```bash
systemctl daemon-reload
systemctl enable --now filebeat
systemctl status filebeat
journalctl -u filebeat -f
```

多台机器:每台有日志的服务器都要部署一个 Filebeat,配置基本一样,只改 `paths` 和 dissect 里的路径前缀。

## 7. 查询使用

### 7.1 Kibana 准备

创建三个 Data View,时间字段选 `@timestamp`:

- `jsy-log-dev-*`
- `jsy-log-test-*`
- `jsy-log-prod-*`

需要跨环境对比时,再建一个 `jsy-log-*`,查询时加 `env: "prod"` 过滤。

Discover 里建议把 `service`、`level`、`trace_id`、`msg` 加为显示列,常用查询点 Save 存成 Saved search。

### 7.2 KQL 查询示例

```
service: "jsy-iot"                                  # 只看某个服务
service: "jsy-iot" and level: "ERROR"               # 某个服务的错误
service: ("jsy-iot" or "jsy-wy")                    # 多个服务
trace_id: "abc123"                                  # 串调用链,按 @timestamp 升序看
user_id: "1001"                                     # 某个用户的日志
msg: "设备离线"                                      # 中文短语(加引号按词组匹配)
service: "jsy-iot" and msg: "心跳超时"
msg.std: "X1A2B3"                                   # 英文标识、序列号、IP 用标准分词字段
parse_error: true                                   # 找格式不匹配的日志
```

### 7.3 Dev Tools 同时搜中文和英文

### 7.4 验证各服务是否都在采集

```json
GET jsy-log-*/_search
{
  "size": 0,
  "aggs": {
    "by_service": {
      "terms": {
        "field": "service",
        "size": 50
      }
    },
    "parse_fail": {
      "filter": {
        "term": {
          "parse_error": true
        }
      },
      "aggs": {
        "by_service": {
          "terms": {
            "field": "service",
            "size": 50
          }
        }
      }

```

- `by_service` 应该列出所有服务,缺哪个就说明那个服务的日志文件名或路径没匹配上。
- `parse_fail` 里出现的服务,就是日志格式与标准不一致的,按第 5 节「个别服务格式不同」处理。

## 8. 常见问题

| 现象               | 排查                                                                                                              |
|------------------|-----------------------------------------------------------------------------------------------------------------|
| 服务没有数据           | `ls -lt /home/logs/<服务>/` 确认活跃日志是否以 `.log` 结尾;超过 48h 未更新的文件会被 `ignore_older` 忽略                                 |
| Kibana 时间差 8 小时  | pipeline 的 date 处理器缺少 `timezone: Asia/Shanghai`                                                                 |
| 没有 `service` 字段  | 路径前缀与 tokenizer 不一致;贴 `filebeat -e` 输出排查                                                                        |
| 写入报 pipeline 不存在 | 先在 ES 创建 `jsy-app-log`,再启动 Filebeat                                                                             |
| 大量 `parse_error` | 该服务格式不同,单独配 input + pipeline                                                                                    |
| 日志重复入库           | 同一目录下有内容重叠的 info / error 文件,用 `exclude_files` 排除其一;`/data/www/jsy-iot/logs` 若是 `/home/logs/jsy-iot` 的软链接,不要重复配置 |
| 中文搜不到或分词太碎       | smartcn 不支持自定义词典;业务术语多的话可换 IK(`ik_max_word` 建索引、`ik_smart` 搜索)                                                  |
| 想重新全量采集          | 停 Filebeat → `DELETE` 对应索引 → `rm -rf /data/www/filebeat/filebeat-8.14.3-linux-x86_64/data/registry` → 启动(会从头重采) |
| 修改映射不生效          | 模板只对新索引生效,已有索引需删除重建或 `_reindex`                                                                                 |
| 调用链串不起来          | traceId 没有跨服务传递;需在网关或 Feign/RestTemplate 拦截器里通过请求头传递,下游放入 MDC                                                   |
| Filebeat 拒绝启动    | `filebeat.yml` 属主必须与运行用户一致,权限 600                                                                               |
